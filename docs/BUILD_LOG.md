## 10-14 上午：找数据

- 最关键的两份文件是自己在惠州政府官网公报栏翻到的：
  《惠州市国民经济和社会发展第十五个五年规划纲要》（惠府〔2026〕13号，
  99 页 PDF）和《2026年惠州市政府工作报告》（官网 HTML，文件下载区是空的，

- 用浏览器抓了第一份热点快照（微博 top30 + 百度 top30），设了每天 09:21
  自动跑的定时任务，时间序列从今天开始攒。

## 10-14 中午：第一轮跑通，结果不对劲

- v1：4621 段 → 4026 清洗后单元 → KMeans k=15，silhouette **0.014**——
  基本等于没有聚类结构。最大的一个簇占了 41%，全是官话套话。
- 语义匹配 22/60 热点有匹配，但人工抽查发现两个离谱的假阳性：
  "这怎么会是一万" 匹配到 "消费量10000"（纯数字巧合），
  还有一个被截断的标题残片相似度 0.955。
  **教训：超短文本片段不能直接拿去做语义匹配。**

## 10-14 下午：重切分

- 写了 `segment_merger.py`，把相邻短句合并成 100~200 字的段落：
  4026 → 863 段，零内容丢失（写了测试验证）。
- 主题图一下子变清楚了（企业/人才、海洋/旅游、材料/AI/电池……），
  最大簇从 41% 降到 16.3%。
- 但匹配召回从 22/60 掉到 8/60——之前定的 0.55 阈值是拍脑袋定的，
  现在证明太严了。扫了一遍阈值：0.50→9/60，0.45→16/60，0.40→24/60。
  光调阈值像是在猜，决定**人工标注一批来定**。

## 10-14 晚上：120 对人工标注（我自己标的）

- 按分数分层抽了 120 对热点–政策段落，我在 Excel 里一行一行标的，
  0=不相关 / 1=部分相关 / 2=直接相关，花了大概 40 分钟。
- 结果让我很意外：**所有 ≥0.60 分的 7 对，全被我标成了 0（不相关）**。
  模型给最高分的地方恰恰是最错的地方——娱乐八卦标题和政策公文
  套话之间有种系统性的误判。结论：**换阈值救不了这个模型**，
  问题在模型本身，不在阈值。
- 这 120 对标注现在是项目的金标准评估集（`data/processed/annotation_batch_20261014.csv`）。

## 10-14 晚上：回到原计划

- 把最初选题3的原文又看了一遍，发现之前走偏了：原计划要的是
  **政策主题之间**的协同关系（关键词共现、主题关联、协同关键节点），
  而我之前做成了政策 vs 热点的对照。热点对照保留为扩展模块，
  主线补回了政策–政策协同分析：关键词共现网络（239节点/307边）、
  主题关联网络、中介中心性找协同关键节点。
- 关键节点：城乡建设（0.275，约第二名两倍）、海洋旅游、工程规划。
  报告里只写"网络结构上的关键节点"，不引申成政策建议——
  共现不等于因果，这是原计划里就强调过的边界。

## 10-14 深夜：模型对决

- 既然老模型不行，用我的 120 对标注当裁判，对决中文领域模型：
  `BAAI/bge-small-zh-v1.5`（约100MB）vs 原来的多语言 MiniLM。
- BGE 赢了：严格口径 F1 0.308 vs 0.158，约两倍；≥0.60 的伪影彻底消失。
  但说实话，赢家的精度也只有 0.22——"更好"，不是"好"。
- 把 `configs/config.yaml` 的默认模型换成 BGE，阈值 0.55→0.45。

## 10-15：v3 重跑，封板

  同快照消融验证：BGE 比老模型多检出 8 个热点——提升确实来自模型，

## 踩过的坑（给后来人）

- GitHub push 工具只支持文本：直接推 PNG base64 会存成损坏的文本文件。
  教训：图一律用 SVG（`svg.fonttype="none"` 体积小），推完下载回来验。
- 单次 push 参数约 115KB 上限：大文件分批推。
- `text_segments.parquet` 里 doc_000/doc_001 被后面的文件复用了，
  做标注批次时 14 对要靠读文本人工消歧——数据源头的问题越早发现越好。
- AppTest 才是真验证：之前只测了 streamlit 健康端点，
  后来发现 plotly 根本没装进 venv。
